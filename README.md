# Соучастник · iOS

Нативная клавиатура для iPhone и iPad, полностью переписанная на Swift. Минимальная версия — **iOS 17**. Android-приложение, Gradle, JNI и Binder удалены; их история остаётся в Git.

Идея оригинального [«Соучастника»](https://github.com/MShverdiakov/souchastnik), автор — [@neuromikhail](https://t.me/neuromikhail): сатирическая клавиатура со словарными пометками и локальным ИИ-разбором текста. Это не юридическая консультация; модель и загруженные справочники могут ошибаться.

## Что работает

- Системное расширение клавиатуры на `UIInputViewController`: RU/EN, цифры и символы, Shift/Caps Lock, «ё»/«ъ» по удержанию «е»/«ь», удаление по словам при удержании, перемещение курсора жестом по пробелу, системная кнопка переключения клавиатур.
- Словарный поиск триггеров с нормализацией регистра, `ё` и пробельных символов. Совпадение со словарём **не выдаётся за вердикт ИИ**.
- Автоматические пометки по словарю: префиксы, точные формы, регистр, многословные имена, отдельные шаблоны для разных видов записей.
- Приложение на SwiftUI: подключение клавиатуры, настройки, импорт словарей и GGUF, поиск по справочнику, локальный разбор текста.
- Локальный llama.cpp b10726 с Qwen3.5: закрытый список ответов `none + кандидаты`, исходный `noneBias = 1.0`, контрпримеры, чат-шаблон с закрытым блоком рассуждения. Санкции берутся только из справочника.
- Отмена и отбрасывание устаревших результатов, ограничение контекста, атомарная установка пакета словарей и замена модели.

## Чего нет в репозитории

Оригинальный автор не опубликовал `articles.json`, `triggers.json`, `agents.json`, `examples.json`, `judge.txt` и веса модели. У владельца этого порта их тоже нет. **Они не восстановлены и не заменены выдуманными данными.**

Без этих файлов приложение собирается, клавиатура печатает, экраны показывают отсутствие данных. Для реальных словарных проверок нужен пакет; для полного ИИ-разбора дополнительно нужны совместимые веса. Синтетические примеры существуют только в тестах и не входят в приложение.

Обычная модель той же архитектуры может загрузиться, но не гарантирует качество исходного обученного варианта. Импорт проверяет заголовок GGUF; архитектура `qwen35` и загрузка контекста проверяются при первом разборе.

## Особенность iOS

В Android модель работала в отдельном сервисе с большим объёмом памяти. iOS не предоставляет расширению клавиатуры эквивалент такого фонового сервиса: расширение исполняется отдельно и ограничено по памяти. Поэтому:

| Где | Возможности |
| --- | --- |
| Клавиатура | Ввод, маркировка и словарные триггеры на последних доступных 400 символах перед курсором |
| Открытое приложение | Полный ИИ-разбор введённой или вручную вставленной фразы |

Модель не линкуется в расширение. Никакой скрытой отправки текста приложению, буфера обмена или фонового сервера нет. Для разбора откройте приложение и вставьте фразу самостоятельно. При нехватке контекста ИИ анализирует хвост текста; интерфейс сообщает об этом.

Ограничения платформы описаны в [документации Apple](https://developer.apple.com/documentation/uikit/creating-a-custom-keyboard). В защищённых полях iOS использует системную клавиатуру; некоторые приложения отключают сторонние клавиатуры. Доступный через `textDocumentProxy` контекст может быть неполным.

## Сборка

Нужны macOS, полный Xcode с iOS SDK, Apple Silicon, CMake и XcodeGen. Проект проверен компиляцией в Xcode 26.2.

```bash
brew install xcodegen cmake
bash scripts/bootstrap.sh
open Souchastnik.xcodeproj
```

Первый запуск скачивает официальный XCFramework b10726 и исходники закреплённой ревизии, проверяет SHA-256 и собирает недостающий **arm64 iOS Simulator**-вариант. На iPhone используется официальный бинарник с Metal, в симуляторе — CPU. Веса модели не скачиваются. `Vendor/`, `third_party/` и сборочные артефакты не включены в Git.

`project.yml` — источник структуры проекта; после его изменения выполните `xcodegen generate`. Сгенерированный `.xcodeproj` включён в репозиторий.

Для устройства в Xcode:

1. Укажите свой Team в обоих targets.
2. При необходимости замените `dev.souchastnik.ios` и `dev.souchastnik.ios.keyboard` на свои bundle IDs.
3. Зарегистрируйте общий App Group и установите **одинаковый** `APP_GROUP_IDENTIFIER` для обоих targets. Значение по умолчанию: `group.dev.souchastnik.ios`.
4. Соберите схему `Souchastnik` для iPhone/iPad. Возможность подписи расширения и App Groups зависит от вашей учётной записи Apple Developer.
5. В iOS: Настройки → Основные → Клавиатура → Клавиатуры → Новые клавиатуры → Соучастник.

Для обмена словарями/настройками между приложением и клавиатурой включите «Разрешить полный доступ». Без него ввод работает; в расширении нет словарей из приложения. Полный доступ не используется для сети: в приложении нет сетевого клиента анализа или аналитики.

## Импорт данных

Во вкладке «Словари» выберите папку с исходными файлами:

| Файл | Обязателен | Формат |
| --- | --- | --- |
| `articles.json` | Да | `articles`: массив `{code, act, title, penalty, severity}` |
| `triggers.json` | Да | `groups`: массив `{words: [String], codes: [String], clean?: String}` |
| `judge.txt` | Да | Системный промпт, содержащий `@@TABLE@@` |
| `agents.json` | Нет | `templates`/`template`, массивы `agents`/`services`; `name`, `forms`, `exact`, `strict`, `kind` |
| `examples.json` | Нет | `shots`: словарь код → массив фраз; `clean` принимается, но общие чистые примеры не добавляются в промпт, как в оригинале |

Каждый входной файл ограничен 2 МБ, общий установленный пакет — 4 МБ. Некорректный импорт не заменяет предыдущий пакет. Неизвестные служебные поля исходных JSON допускаются; установка использует только поля, нужные iOS. Исходные файлы не изменяются. После импорта переоткройте клавиатуру.

GGUF импортируется отдельно. Поддерживается и прежнее имя `libmodel-qwen35-08b-q40.so`, если внутри действительно GGUF. Модель хранится в приватном контейнере приложения, не в App Group, и исключена из резервного копирования. Исходный pipeline LoRA → f16 → imatrix → Q4_0 сохранён в `tools/make_gguf.sh`, теперь с выходом `.gguf`. Для него отдельно нужны Python ML-зависимости, адаптер и русский корпус, как в оригинальном проекте.

## Проверка

```bash
swift test
xcodebuild -project Souchastnik.xcodeproj -scheme Souchastnik \
  -sdk iphonesimulator -configuration Debug \
  -derivedDataPath build/DerivedData CODE_SIGNING_ALLOWED=NO build
xcodebuild -project Souchastnik.xcodeproj -scheme Souchastnik \
  -sdk iphoneos -configuration Release \
  -derivedDataPath build/Device CODE_SIGNING_ALLOWED=NO build
```

Тесты ядра проверяют триггеры, маркировку, совместимость данных, промпт, приоритет `none`, общие префиксы токенов и регистр. Дополнительные шаги проверки на устройстве — в [Documentation/Validation.md](Documentation/Validation.md). Проверка реального качества ИИ требует отсутствующих оригинальных данных и весов.

## Структура

- `iOS/App` — SwiftUI, импорт и локальный `LocalJudge`.
- `iOS/Keyboard` — самостоятельное расширение UIKit.
- `iOS/Shared` — общий контейнер словарей и настроек.
- `Sources/SouchastnikCore` — платформонезависимое Swift-ядро, без UIKit и llama.cpp.
- `Tests` — синтетические тесты; не правовой справочник.
- `scripts` — воспроизводимая подготовка зависимостей.
- `tools` — сохранённые инструменты работы с оригинальными ИИ-данными.
